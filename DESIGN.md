# JRPG-бой для Hytale — дизайн

Цель: пошаговые бои в духе Final Fantasy X / Expedition 33 внутри Hytale. Игрок + минимум 2 компаньона против группы врагов, меню способностей/предметов, кинематографичная камера, кастомные анимации и эффекты.

Метки достоверности API:
- ✅ **подтверждено** документацией/гайдами (ссылки внизу);
- ⚠️ **не проверено** — есть косвенные признаки, нужно проверить на реальном сервере;
- ❌ **нет в API** — нужен обходной путь.

---

## 1. Архитектура: два слоя

```
┌──────────────────────────────┐      события (BattleListener)      ┌──────────────────────────────┐
│ battle-core (чистая Java)    │ ─────────────────────────────────▶ │ hytale-plugin (адаптер)      │
│ правила боя, очередь ходов,  │                                     │ камера, частицы, анимации,   │
│ статусы, способности, ИИ     │ ◀───────────────────────────────── │ UI-меню, NPC, старт боя      │
└──────────────────────────────┘      команды игрока (BattleAction)  └──────────────────────────────┘
```

**Почему так:** API Hytale ещё меняется (ранний доступ, апдейты ломают моды). Вся логика боя живёт в `battle-core` без зависимостей от Hytale: её можно тестировать без игры, а при обновлении Hytale чинится только адаптер. Ядро ничего не знает о камере и частицах; оно лишь сообщает «ход начался», «способность применена», «урон 42», а адаптер превращает это в зрелище.

Плагин Hytale — серверный Java-плагин (`JavaPlugin`, `manifest.json`, жизненный цикл `setup()/start()/shutdown()`) ✅. Модели, анимации, частицы и UI-разметка идут отдельным asset pack внутри плагина (`IncludesAssetPack: true` в манифесте) ✅.

## 2. Как игрок начинает бой

Выбран вариант **«символьные встречи»** (как в FF X-2 / Expedition 33): враги видны в мире, бой начинается при контакте.

1. Враг-«лидер» группы — NPC с компонентом `EncounterComponent` (id группы врагов из JSON).
2. Перехват урона: ECS-система в группе damage-фильтра ловит удар игрока по такому NPC, **отменяет урон** и вызывает `BattleManager.start(...)`. ✅ (пайплайн урона Gather/Filter/Inspect и `EntityTickingSystem` подтверждены; точное имя класса фильтр-системы ⚠️).
3. Кто ударил первым:
   - игрок ударил врага → **преимущество**: партия получает +50% к стартовой инициативе;
   - враг ударил игрока → **засада**: враги ходят первыми.
4. Для отладки — команда `/jrpg battle <groupId>` ✅ (`AbstractPlayerCommand`).

**Арена:** бой идёт прямо на месте (без загрузки отдельного мира). Точка центра = позиция встречи. Партия ставится в линию с одной стороны, враги — с другой (teleport через `TransformComponent`) ✅. На время боя у всех участников отключается обычный ИИ/движение (флаг-компонент `InBattleComponent`; поведение NPC блокируем через его Role ⚠️), игроку блокируем движение через `movementMultiplier = (0,0,0)` в настройках камеры ⚠️.

**Конец боя:** победа → опыт/лут, возврат камеры (`SetServerCamera(Custom, false, null)`) ✅; поражение → респаун у точки отдыха; бегство → шанс от скорости.

## 3. Пошаговая система: CTB-таймлайн

Выбран **Conditional Turn-Based (как в FF X)**, а не «раунды»:

- У каждого бойца есть `ct` (счётчик готовности). Каждый тик `ct += speed`. Кто первый достиг `100` — ходит, после хода `ct -= 100` (с учётом «веса» действия: тяжёлые способности = 120, лёгкие = 80).
- Тики симулируются мгновенно (без реального времени) → игрок видит **прогноз следующих 8 ходов** сверху экрана, и он меняется от «Ускорения»/«Замедления».
- Поэтому ходы могут идти не по кругу: быстрый персонаж походит 2 раза до медленного босса.

Фазы одного хода (state machine в `Battle`):

```
TURN_START → (тики статусов: яд, реген, +энергия)
          → если оглушён → TURN_END
          → AWAIT_COMMAND (игрок: меню / враг: ИИ)
          → EXECUTE (ядро считает результат сразу)
          → PRESENTATION (адаптер играет анимацию; ядро ждёт ack)
          → TURN_END (длительности статусов −1, проверка победы)
```

Ядро считает результат действия мгновенно и детерминированно, а адаптер потом «проигрывает» его. Анимация не влияет на правила — это упрощает отладку и даёт возможность позже добавить QTE/парирование как модификатор (как в E33) отдельным шагом.

## 4. Ресурсы и статусы с таймерами

**Ресурсы бойца:** HP, MP (для магии), **AP / энергия** (как в E33: +1 в начале каждого своего хода, базовая атака даёт ещё +1, способности тратят 1–5 AP, максимум 10).

**Статусы** (`StatusEffect`): id, длительность **в своих ходах**, сила, момент срабатывания.

| Статус | Когда тикает | Эффект |
|---|---|---|
| Яд (Poison) | начало хода | −`power`% от макс. HP, не убивает ниже 1 (настраивается) |
| Горение (Burn) | конец хода | фикс. урон, стакается до 3 |
| Реген (Regen) | начало хода | +`power`% HP |
| Ускорение (Haste) | пассивно | speed ×1.5 → чаще ходы |
| Замедление (Slow) | пассивно | speed ×0.5 |
| Оглушение (Stun) | начало хода | пропуск хода |
| Защита (Guard) | пассивно | −50% входящего урона до следующего хода |
| Заряд (Charged) | пассивно | следующая способность +50% урона, снимается |

Длительность уменьшается в TURN_END владельца. Повторное наложение: обновляет длительность (или стакается, если `stackable`). Всё описывается в JSON, новый статус = новая запись + (если нужно особое поведение) маленький класс-обработчик.

## 5. Меню боя (UI)

Используем кастомные страницы Hytale: `InteractiveCustomUIPage` + `.ui`-разметка в asset pack, события кнопок через `UIEventBuilder.addEventBinding(Activating, "#Button", ...)` ✅.

```
[Атака] [Способности ▸] [Предметы ▸] [Защита] [Бегство]
         └ список: Огненный удар  3 AP | Лечение 12 MP ...
                    └ выбор цели: стрелками/кликом по списку целей
```

- Страница открывается в начале хода персонажа партии, `CustomPageLifetime.CantClose` ✅.
- Недоступные пункты (мало AP/MP) затемнены.
- Таймлайн ходов и полоски HP/AP партии — отдельный HUD ⚠️ (кастомный HUD есть в моддинге, точный API не проверен; запасной вариант — блок в той же странице).
- Компаньонами в прототипе управляет игрок (как в FF). Позже — переключатель «авто» для каждого.

## 6. Камера боя

Камера управляется пакетом `SetServerCamera(ClientCameraView.Custom, true, ServerCameraSettings)` ✅. Доступны: `distance`, `rotation (yaw/pitch/roll)`, `rotationType = Custom`, `positionLerpSpeed`/`rotationLerpSpeed` (плавный перелёт), `displayCursor`, `mouseInputType`, `isLocked`, `movementMultiplier` ✅/⚠️.

Ракурсы (`CameraDirector` в адаптере):

| Момент | Ракурс |
|---|---|
| Старт боя | общий план: высокий pitch (~−35°), distance 14–18, видно обе стороны |
| Ход персонажа | наезд к персонажу: distance 4, сбоку-сзади, lerp 0.15 |
| Выбор цели | плавный поворот на выбранную цель |
| Удар | короткий «удар камерой» по анимации, затем назад к общему плану |

**Ограничение ⚠️:** подтверждённые настройки камеры строятся **относительно сущности игрока**. Чтобы «лететь» к компаньону или врагу, есть два пути:
1. В протоколе есть поля смещения/привязки позиции (`positionOffset`, `attachedToType`/`attachedToEntityId` — по распакованному серверу) ⚠️ — проверить первым делом.
2. Запасной: во время боя игрок-персонаж становится «невидимой точкой зрения». Его настоящая модель заменяется NPC-двойником на арене, а сам игрок (невидимый, без коллизии) телепортируется в точку обзора. Так мы получаем полный контроль камеры. ✅ (телепорт и невидимость стандартны), но сложнее.

## 7. Подсветка выбора частицами

`ParticleUtil.spawnParticleEffect(name, position, ..., playerRefs, accessor)` ✅ (17 перегрузок, есть scale, color, maxDuration, привязка к source-сущности).

- Своя система частиц `JRPG_SelectRing` (asset pack, кольцо на земле, цвет параметром): **синее** — чей ход, **красное** — выбранная цель-враг, **зелёное** — цель-союзник.
- Кольцо перезапускается каждые ~0.5 с, пока выбор активен (или одним эффектом с `maxDuration`).
- Отправляется только участникам боя (`playerRefs`) — другие игроки на сервере его не видят.

## 8. Кастомные анимации и эффекты

Модели и анимации делаются в **Blockbench** (официальный плагин Hytale) ✅ → `.blockymodel` + `.blockyanim` в asset pack ✅. Запуск анимации на NPC: `NPCEntity.playAnimation(...)` / компонент `ActiveAnimationComponent` ✅ (имена есть), точная сигнатура ⚠️.

**Ключевое решение:** каждая способность — это JSON-описание с **таймлайном**, а не код. Героям и врагам — один и тот же формат.

```json
{
  "id": "fire_slash",
  "name": "Огненный разрез",
  "cost": { "ap": 3 },
  "target": "SINGLE_ENEMY",
  "power": 1.6, "element": "FIRE",
  "applies": [{ "status": "burn", "chance": 0.5, "turns": 3 }],
  "sequence": [
    { "t": 0.00, "do": "camera", "shot": "actor_close" },
    { "t": 0.00, "do": "move_to_target", "offset": 1.5 },
    { "t": 0.40, "do": "anim", "who": "actor", "anim": "FireSlash" },
    { "t": 0.75, "do": "particles", "at": "target", "fx": "Fire_Hit_Big" },
    { "t": 0.75, "do": "hit" },
    { "t": 0.75, "do": "sound", "id": "SFX_Fire_Slash" },
    { "t": 0.80, "do": "anim", "who": "target", "anim": "Hurt" },
    { "t": 1.40, "do": "move_back" },
    { "t": 1.80, "do": "camera", "shot": "overview" }
  ]
}
```

- `hit` — момент, когда показываются цифры урона/статусы (результат уже посчитан ядром).
- `SequencePlayer` в адаптере исполняет шаги по тикам мира.
- Новая атака врага = модель/анимация в Blockbench + JSON. Код писать не нужно.

## 9. Партия (минимум 3)

- Игрок + 2 компаньона (NPC с собственной Role: вне боя следуют за игроком, в бою подчиняются ядру) ⚠️ (Role/поведение NPC настраиваются JSON-ассетами, точный формат следования проверить).
- Данные партии (уровень, статы, экипировка, выученные способности) хранятся как компонент на игроке с codec → сохраняются вместе с игроком ✅ (механизм `BuilderCodec` подтверждён).
- Состав и классы стартовой партии — `data/party.json`.

## 9a. Расстановка врагов, уникальные боссы, без случайного спавна

**Принцип: в мире нет случайных встреч.** Враги появляются только там, где их поставил автор.

1. **Встречи как данные** (`battle-core/src/main/resources/data/encounters.json`, в Hytale ещё и копия в папке данных плагина, которую можно править без пересборки). Каждая встреча задаёт:
   - `location`: мир, координаты и радиус срабатывания;
   - `enemies`: какие враги и где стоят на арене;
   - `unique`: одноразовая (босс), после победы исчезает навсегда;
   - `respawnMinutes`: для обычных, через сколько они вернутся (0 = никогда);
   - `canFlee`: можно ли сбежать;
   - `intro`: реплики в начале;
   - `phases`: фазы босса по HP;
   - `script`: эксклюзивный Java-скрипт;
   - `loot`, `exp`: награда.
2. **Шаблоны врагов** (`enemies.json`): статы, способности, модель, флаг `boss`, `immunities` (например, босс не оглушается).
3. **Фазы босса без кода:** при HP ниже порога срабатывает реплика, появляются новые способности, убираются старые, накладываются статусы на себя и призывается подмога. Каждая фаза срабатывает один раз.
4. **Эксклюзивные механики кодом:** класс `BattleScript` с хуками `onBattleStart`, `onTurnStart`, `overrideAction` (принудительный ход босса) и `afterAction`. Пример: `SpiderQueenScript`. Пока живы паучата, королева получает вдвое меньше урона, а каждый её 3-й ход это «Кокон» на самого здорового героя. Скрипт подключается одной строкой в `GameData.BOSS_SCRIPTS`.
5. **Прогресс мира** (`WorldProgress`) хранит, какие боссы побеждены и когда зачищены обычные встречи.

**Ванильные мобы Hytale.** Чтобы обычные мобы не мешали, есть три уровня (✅, это настройки самого Hytale):
- весь мир: в настройках мира, Simulation Settings, выключить **NPC Spawning** (и **Spawn Markers**);
- только зона вокруг логова: ассет `SpawnSuppression` (радиус, подавляемые группы NPC, `suppressSpawnMarkers`);
- чтобы враг стоял в мире видимым до боя, используется `SpawnMarker` с точными координатами и `ManualTrigger`. Либо плагин сам спавнит NPC встречи, когда игрок подходит.
