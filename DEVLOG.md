## Перенос проекта / как запустить

**Что нужно:** JDK 21+ (для плагина JDK 25, как требует сервер Hytale). Gradle ставить не надо, в проекте есть `gradlew`.

```
jrpg-mod/
├─ DESIGN.md        дизайн боя и статус проверки API Hytale (✅/⚠️)
├─ DEVLOG.md        этот журнал
├─ play.bat / play.sh  запуск консольного прототипа
├─ gradlew, gradle/    обёртка Gradle (сама скачивает Gradle)
├─ settings.gradle  корневой Gradle (battle-core + hytale-plugin)
├─ battle-core/     ЛОГИКА БОЯ, без зависимостей от Hytale
└─ hytale-plugin/   АДАПТЕР к Hytale (камера, частицы, меню, NPC)
```

Команды (из папки `jrpg-mod/`):
- **играть в прототип:** `play.bat` (Windows) или `sh play.sh`. Выбираешь встречу на «карте» и управляешь партией цифрами.
- автобой: `play.bat --auto --encounter spider_queen_lair --seed 5`
- тесты ядра: `gradlew test`
- мод: `gradlew :hytale-plugin:jar` (нужна JDK 25). `HytaleServer.jar` для компиляции Gradle сам скачивает с `maven.hytale.com` (версия в `hytale-plugin/build.gradle`, `hytaleVersion`, сейчас 0.7.2; другая: `gradlew :hytale-plugin:jar -PhytaleVersion=0.7.1`). Свой jar можно положить в `hytale-plugin/libs/HytaleServer.jar`, тогда берётся он. Результат: `hytale-plugin/build/libs/JrpgBattles-<версия>.jar` → в папку `mods` (сервер) или `Saves/<мир>/mods` (одиночная игра).
- GitHub: выбран репозиторий `fsfwfwefWEF/Hyplug` (шаблон плагина Hytale). `hp` его копия, `hyta` это инструмент разбора сервера (Orbis Prism), `hyrp` это исходники сайта hytale-docs.com, по ним сверялось API. Запушить код пока нельзя, у Claude нет прав на запись (нужно установить Claude GitHub App).

Перенос в другое место = скопировать папку `jrpg-mod/` целиком (или залить в git-репозиторий; `.gitignore` уже есть). Никаких внешних путей проект не использует.

### Что за что отвечает (battle-core, пакет `dev.jrpg.battle`)

| Файл | Роль |
|---|---|
| `Battle` | Машина состояний боя: старт, ход, статусы, действия, конец боя. Главный класс. |
| `TurnQueue` | CTB-очередь: кто ходит следующим, прогноз ходов. |
| `Combatant`, `Stats`, `Side` | Боец, его характеристики, HP/MP/AP/ct, статусы. |
| `StatusDef`, `StatusInstance`, `StatusApply` | Статусы (яд, горение, реген, ускорение, оглушение, защита, заряд) и их наложение. |
| `Ability`, `Item`, `TargetType` | Способности и предметы (предмет = способность без стоимости). `sequenceId` → имя анимационного таймлайна. |
| `BattleAction` | Команды хода: Атака, Способность, Предмет, Защита, Бегство. |
| `ActionResult` | Посчитанный итог действия: урон, лечение, статусы, кто пал. |
| `BattleListener` | Интерфейс событий ядра → адаптер. Его реализуют консольное демо и Hytale-плагин. |
| `EnemyAI` | Простой ИИ врагов. |
| `Content` | Реестр статусов, способностей, предметов (пока в коде) + стартовая партия. |
| `GameData` | Загрузка `enemies.json`/`encounters.json`, сборка боя для встречи, лут, реестр скриптов боссов `BOSS_SCRIPTS`. |
| `Encounter`, `EnemyTemplate` | Встреча в конкретном месте мира и шаблон врага (JSON). |
| `BattleScript` | Хуки для уникальных механик встречи. |
| `PhaseScript` | Фазы босса по HP из JSON. |
| `scripts/SpiderQueenScript` | Пример эксклюзивного босса. |
| `WorldProgress` | Какие боссы побеждены, когда зачищены обычные встречи. |
| `resources/data/*.json` | **Сюда ставятся враги и встречи.** |
| `demo/ConsoleDemo` | Текстовый «адаптер» для проверки боя без игры. |

### Что за что отвечает (hytale-plugin, пакет `dev.jrpg.hytale`)

| Файл | Роль |
|---|---|
| `JrpgPlugin` | Точка входа мода: загрузка json, команда, планировщик пауз, автостарт встреч. |
| `JrpgCommand` | `/jrpg start <id>`, `list`, `menu`, `stop`, `reload`, `particle <имя>`. |
| `BattleSession` | Один бой игрока: арена, NPC-куклы врагов и компаньонов, события ядра → меню/чат/частицы, паузы между ходами. |
| `BattleMenuPage` | UI-страница боевого меню (кнопки → `BattleMenu` ядра). |
| `EncounterWatcher` | Раз в секунду: игрок в радиусе встречи → бой. |
| `Fx` | Камера, частицы, подписи над NPC, перемещения; любые сбои пишутся в лог одним предупреждением. |
| `Settings` | Чтение `settings.json`. |
| `resources/Common/UI/Custom/JrpgBattle/BattleMenu.ui` | Разметка меню. |
| `resources/manifest.json` | Манифест мода. |

Ядро также содержит `BattleMenu` (модель меню: экраны, пункты, переходы) и `BattleText` (строки для HUD), их можно проверять тестами без игры.

### Файлы, которые правятся без пересборки
При первом запуске мод копирует `enemies.json`, `encounters.json` и `settings.json` в свою папку данных на сервере (путь печатается в логе и командой `/jrpg reload`). Правишь их и выполняешь `/jrpg reload`.

### Как добавить контент
- **Встреча в определённом месте:** новая запись в `encounters.json` (координаты, враги, `unique`, лут).
- **Враг:** запись в `enemies.json`.
- **Уникальный босс:** шаблон с `"boss": true` + встреча с `unique: true` и `phases`. Если нужна особая логика, класс в `scripts/` реализует `BattleScript`, и его id добавляется в `GameData.BOSS_SCRIPTS`.
- **Статус:** `c.add(new StatusDef(...))` в `Content.demo()`. Новое поведение = новое значение `StatusDef.Kind` + ветка в `Battle.tickStatuses`/`multiplier`.
- **Способность:** `c.add(...)` в `Content.demo()` и id в список способностей бойца. Анимация потом привязывается по `sequenceId`.
- **Предмет:** `new Item(id, name, эффект-Ability)` + количество в `demoInventory()`.

## 2026-10-17: сессия 1, дизайн и прототип ядра

**Сделано**
- `DESIGN.md`: архитектура «ядро + адаптер», старт боя через символьные встречи, CTB-очередь, AP/энергия в духе E33, статусы с таймерами, меню, камера, кольца частиц, анимации как JSON-таймлайны, партия из 3. Отмечено, что из API Hytale подтверждено, а что нет.
- `battle-core`: рабочее ядро пошагового боя. 8 тестов проходят (`gradle :battle-core:test`), консольное демо проводит полный бой 3×3.
- `hytale-plugin`: каркас адаптера (плагин, `/jrpg`, сессия боя, камера). **Не компилировался**, потому что нет `HytaleServer.jar`. Имена классов взяты из документации и гайдов сообщества, а места с непроверенными сигнатурами помечены `⚠️`.

**Как работает ход** (`Battle`)
1. `TurnQueue.advance` двигает время, пока кто-то не наберёт `ct ≥ 100`.
2. Начало хода: +1 AP, срабатывают статусы с `TURN_START` (яд, реген). При оглушении ход пропускается.
3. Враг: `EnemyAI` сразу выбирает действие. Партия: фаза `AWAIT_COMMAND`, адаптер показывает меню и вызывает `submit(action)`.
4. Результат считается сразу, фаза `PRESENTING`, адаптер проигрывает анимацию и вызывает `acknowledge()`.
5. Конец хода: `ct -= weight` действия, статусы `TURN_END` (горение), длительности уменьшаются на 1. Статус, наложенный на себя в этом ходу (например, Защита), не уменьшается до следующего хода.

**Решения, принятые по умолчанию** (можно поменять)
- CTB (как в FF X) вместо раундов: у быстрых персонажей больше ходов, есть прогноз очереди.
- Длительность статусов считается в ходах владельца, а не в секундах.
- Яд не опускает HP ниже 1, горение может убить.
- Компаньонами в бою управляет игрок.
- Контент пока задан в Java-коде (`Content.demo()`). Переезд в JSON запланирован.

**Дальше** (этапы из DESIGN.md §11)
1. Получить `HytaleServer.jar`, собрать плагин и исправить сигнатуры с `⚠️`.
2. Спавн и расстановка NPC на арене, блок движения.
3. Меню на `InteractiveCustomUIPage`.
4. Камера: проверить привязку к чужой сущности.
5. Ассет `JRPG_SelectRing`, `SequencePlayer` для анимаций.

## 2026-10-17: сессия 2, встречи, уникальный босс, запуск прототипа

**Сделано**
- Встречи и враги вынесены в JSON (`resources/data/encounters.json`, `enemies.json`), у каждой встречи есть координаты в мире. Случайных встреч нет.
- Уникальный босс «Королева пауков Арахна» (`spider_queen_lair`):
  - вступительные реплики;
  - фазы на 60% HP (кислотный дождь и призыв паучат) и на 25% HP (ярость с ускорением);
  - иммунитет к оглушению и замедлению, сбежать нельзя;
  - гарантированный уникальный лут «Клык королевы»;
  - после победы босс больше не появляется.
- Эксклюзивная механика кодом (`SpiderQueenScript`): «Защита выводка» и «Кокон» каждый 3-й ход.
- Ядро: `BattleScript` (хуки), `summon`, `say`, фазы, иммунитеты, запрет бегства.
- Удобный запуск: `play.bat`/`play.sh`, Gradle-обёртка. Консольный прототип: карта встреч, бой, лут сохраняется между боями.
- Плагин: старт боя по id встречи, реплики/призыв/фазы выводятся в чат, отметка победы в прогрессе (не собирался, нет `HytaleServer.jar`).
- 14 тестов проходят. При случайной игре автопилота партия выигрывает у босса примерно в 8 из 10 боёв (seed 1–10).

**Как работает босс**
`GameData.createBattle` собирает скрипт из трёх частей: реплики intro, `PhaseScript` из JSON и Java-скрипт по `script`. Бой вызывает хуки скрипта в начале боя, в начале каждого хода, перед ходом врага (может подменить действие) и после каждого действия.

**Дальше**
- `HytaleServer.jar`, затем сборка плагина и спавн NPC встречи по координатам.
- Триггер входа в зону встречи (`EncounterTriggerSystem`).
- Перенести статусы/способности/предметы тоже в JSON.

## 2026-10-17: сессия 3, мод для игры: меню боя и плагин

**Сделано**
- Боевое меню в игре (`BattleMenuPage` + `BattleMenu.ui`): панель внизу экрана.
  - Слева партия (HP/MP/AP/статусы) и враги.
  - В центре очередь ходов и журнал боя.
  - Справа кнопки: Атака / Способности / Предметы / Защита / Бегство, затем выбор цели и «Назад».
- Логика меню вынесена в ядро (`BattleMenu`), покрыта тестами (всего 20 тестов, все проходят).
- `BattleSession`:
  - арена на месте игрока, герой это сам игрок;
  - компаньоны и враги спавнятся NPC-куклами (замороженные, неуязвимые, с подписью «имя HP»);
  - атакующий «выходит» к цели и возвращается, павшие исчезают;
  - между ходами пауза `actionDelayMs`.
- Старт боя: подойти к точке встречи (`EncounterWatcher`, после боя 30 с перерыв) или `/jrpg start <id>`.
- Камера общего плана (`SetServerCamera`), возврат после боя.
- Частицы по именам из `settings.json` (по умолчанию выключены, потому что имена ванильных частиц неизвестны; проверка: `/jrpg particle <имя>`).
- JSON читается своим парсером (`Json`), без Gson, чтобы не конфликтовать с сервером.

**Не проверено в игре** (код сверен с документацией hytale-docs.com, но против настоящего `HytaleServer.jar` ещё не компилировался):
- имена ролей NPC (`Trork_Warrior`, `Spider`, `Slime`, `Kweebec_Seedling`): если роли нет, кукла не появится, в логе будет `[JRPG] Роль NPC не найдена`;
- метод обновления UI `sendUpdate(cmd, false)` (в документации встречается и `update(false, cmd)`);
- поворот (yaw) у Teleport и камеры: могут смотреть не в ту сторону, правится в `settings.json` → `camera.yaw`.

**Ограничения прототипа**
- Камера не «летит» к компаньону, потому что API камеры привязан к игроку. Чей ход, показывает «▶» в подписи над головой и в меню.
- Анимаций атак пока нет (нужны id анимаций моделей). Вместо них подход к цели.
- Инвентарь боевых предметов и прогресс боссов живут в памяти до перезапуска сервера.

## 2026-10-17: сессия 4, первая сборка мода

**Сделано**
- Мод впервые скомпилирован против настоящего сервера Hytale 0.7.2 (с `maven.hytale.com`) и собран в `JrpgBattles-0.3.0.jar`.
- Исправлено под API 0.7.x:
  - векторы теперь из JOML: `org.joml.Vector3d` вместо `com.hypixel.hytale.math.vector.Vector3d`;
  - поворот: `com.hypixel.hytale.math.vector.Rotation3f(pitch, yaw, roll)` вместо `Vector3f`;
  - у команд нет `canGeneratePermission()`, вместо него `requireNoPermission()` в конструкторе (команды доступны всем);
  - игрок перемещается через `Teleport.createForPlayer(...)` (`Fx.teleportPlayer`, `Fx.teleport` сам определяет игрока).
- Сборка больше не требует класть `HytaleServer.jar` вручную: зависимость `com.hypixel.hytale:Server` из Maven Hytale.
- Проверка: сервер 0.7.2 в режиме `--bare` загружает мод, `setup()` проходит (в логе `JRPG Battles: загружено встреч 2`). Полный запуск мира здесь невозможен (нет ассетов игры), поэтому меню, NPC и камера проверяются в игре по логам.

**Замечания**
- Папка данных мода: `mods/Hveien_JrpgBattles/` (json-файлы). Сервер пишет про неё `Skipping pack ... missing manifest.json`, это безвредно.
- Сигнатуры, которые ещё не проверены в игре: разметка `BattleMenu.ui` (клиент), роли NPC, камера.
